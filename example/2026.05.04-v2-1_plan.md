### 핵심 아키텍처 — iframe ↔ 부모 통신

iframe 안에서 사용자가 요소를 클릭하면, 부모로 메시지를 보내야 합니다. 두 가지 방법이 있어요:

**A안: postMessage** (전통적, sandbox-friendly)
- iframe에 스크립트 주입 → click 핸들러 → `parent.postMessage(...)`
- 장점: 격리 보장
- 단점: 매번 메시지로 통신, 오버헤드 약간

**B안: same-origin 직접 접근** (현재 방식)
- 부모가 `iframe.contentDocument` 직접 접근해서 이벤트 리스너 등록
- 장점: 빠르고 직관적, srcdoc은 same-origin
- 단점: sandbox 보안 약화

→ **B안 추천**. 이미 `srcdoc` + `allow-same-origin` 사용 중이라 자연스럽고, 신뢰된 사용자 HTML이라 보안 이슈도 없어요.

### 데이터 플로우 (편집 사이클)

```
1. 사용자가 iframe 안 요소 클릭
2. 부모가 contentDocument에서 click 캐치
3. 선택 요소 정보(selector, computed styles) → Zustand store
4. 인스펙터 패널이 store 구독해서 렌더링
5. 사용자가 인스펙터에서 색상 변경
6. ① 즉시 iframe DOM에 인라인 스타일 패치 (낙관적 업데이트)
   ② 동시에 코드 패널의 HTML 문자열도 갱신
7. 변경 직전 스냅샷을 history 스택에 push (undo용)
```

### 셀렉터 전략 (가장 까다로운 부분)

선택한 요소를 코드에서 다시 찾으려면 안정적인 셀렉터가 필요해요:

1. **고유 셀렉터 생성**: `id`가 있으면 `#id`, 없으면 부모 체인 + `:nth-child()`
   - 예: `body > div.s1 > h1:nth-child(4)`
2. **HTML 문자열 패치**: 새 HTML을 파싱 → 같은 셀렉터로 요소 찾기 → 인라인 스타일 적용 → `outerHTML` 다시 덤프
3. 라이브러리 사용: `unique-selector` 또는 직접 구현

### 컬러 팔레트 자동 감지 로직

```typescript
// :root { --brand-primary: #EE5106; ... } 자동 감지
const cssRules = iframeDoc.styleSheets;
const rootVars = extractCustomProperties(":root");
// → [{ name: "--brand-primary", value: "#EE5106" }, ...]
// 사용자가 패널에서 색상 변경 → :root 스타일에 새 값 주입
// → 모든 컴포넌트가 자동으로 업데이트
```
